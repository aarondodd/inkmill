# Inkmill

Terminal word processor for Markdown, built 2026-11-02 at Aaron's request as a
new app inspired by WordGrinder (not a port), with a WordPerfect 5.1 for DOS
look. Public repo (made public by Aaron 2026-11-02) https://github.com/aarondodd/inkmill, trunk-based on main.

## Requirements as Aaron stated them

- Python, a modern TUI framework (chose Textual 8).
- Markdown is the primary format; WordGrinder's native format is out of scope.
- Standard top menu bar (File, Edit, ...) that stays hidden and opens on a
  hotkey, for focus-free writing (Esc, F10, Alt+=; Alt+letter opens a menu).
- Default theme WordPerfect 5.2 for DOS style: blue background, white text.
- Built-in file management like WordPerfect, with preview before open and
  multiple open documents (F5 List Files).
- Latest Markdown features: footnotes and tables at minimum.
- No in-app preview; CSS-styled HTML output, and "preview" opens the default
  browser.
- Must run on Windows, Linux and Termux on Android.
- Designed to be extended.

## Layout

See `docs/architecture.md`. Core idea: every action is a `Command` in one
registry; key bindings (priority bindings gated by `check_action` so they go
quiet in dialogs), menus and the Ctrl+P palette are views over it. Plugins
(`register(api)`, plugins folder or `inkmill.plugins` entry point) use the
same registry. One `InkEditor` (TextArea subclass) per document inside a
ContentSwitcher.

## Decisions worth keeping

- All runtime deps are pure Python (textual, markdown-it-py, mdit-py-plugins,
  linkify-it-py, platformdirs, tomli-w) for Termux. tree-sitter highlighting
  is the optional `[syntax]` extra.
- No binding on Ctrl+I/M/H (terminals send Tab/Enter/Backspace). Bold Ctrl+B,
  italic Ctrl+E, footnote Ctrl+F7 (WordPerfect's), go back Alt+B, tidy table
  Ctrl+\.
- Termux preview: loopback HTTP server plus `termux-open-url`, since Android
  browsers cannot read Termux private storage. WSL: `wslview`/`explorer.exe`.
- platformdirs with `appauthor=False` so Windows paths are
  `%LOCALAPPDATA%\inkmill`, not `inkmill\inkmill`.
- Opening a file replaces a lone empty Untitled; File > New never does (a bug
  caught by tests on day one).

## Plugins (0.2.0)

Aaron's 0.2 asks: a plugin manager UI fed from the repo's `plugins/` folder
(online or a local clone for offline use), plugins versioned with a minimum
Inkmill version, update check and apply, reload without copying files; and
two plugins, Git Sync and a chapter/related-documents plugin (named Binder).

- Managed plugin = `plugins/<id>/plugin.toml` + `__init__.py`, loaded as
  package `inkmill_plugin_<id>`. `requires_inkmill` is a PEP 440 specifier
  (`packaging` added as a dep, pure Python).
- `plugins/index.json` is generated by `scripts/build_plugin_index.py`
  (sha256 per file). CI runs `--check --base <main's index>`: stale index or
  changed files without a version bump fails. Editing any plugin file means
  rebuilding the index, or the hash check rejects installs (tests catch it).
- `.gitattributes` pins `plugins/**` to LF so Windows clones hash the same.
- Online source default is raw.githubusercontent.com on `main`; testing a
  branch before merge needs `index_url` pointed at the branch, or a local clone.
- Restart is in-process (`__main__.run_app` loop + `Handoff`), not
  `os.execv`, because of Windows terminals. Undo history is lost on restart.
- Git Sync: no vault; repo = whatever contains the document. Optional
  per-repo table `[plugins.git_sync.repos."<posix path>"]`. git runs with
  `GIT_TERMINAL_PROMPT=0`, ssh BatchMode (unless the user set core.sshCommand),
  `LC_ALL=C` for parseable errors; verified an unauthenticated HTTPS and SSH
  push fail in under a second with advice. Pull is ff-only, offers rebase on
  divergence, aborts on conflict.
- Binder: order lives in the binder's `contents`; chapters carry `parent`;
  explicit `previous`/`next` override; `related` list; `up`/`prev` read as
  aliases. Paths relative with forward slashes. Footnote labels are prefixed
  per chapter in the manuscript export.
- Themes plugin (added to the same PR at Aaron's request): theme files are
  TOML (`name`, `dark`, `background`, `foreground`, `primary`, optional
  `accent`, `[ui]` overrides); bundled ones in `plugins/themes/themes/`, user
  ones in `<config>/themes/`, saving one applies it. Core `derive_variables`
  computes im-* per theme in `get_theme_variable_defaults`. Theme names and
  descriptions say "inspired by" a kind of program and avoid product names.
- Found while building the gallery: app CSS `Screen { background }` made every
  modal opaque (dialogs drew over a blank page since 0.1). Removed; Screen's
  own default background still applies to the base screen.
- Aaron chose Alt+F5 navigator and Ctrl+F12 commit by accepting the design
  defaults; not yet tried in his terminals (Alt+PgUp/PgDn/Up may not pass
  through everywhere).

## Writer plugins (0.3.0)

Aaron accepted every proposed writer plugin (2026-11-03) and asked for
dependency checks at install. Built as 10 new plugins plus Binder 1.1, with
core APIs they share: SidePanel (`#main` horizontal row, not docked;
`_repaint_editors` after open/close because TextArea re-wraps but keeps
painting the old wrap), decorations (`InkEditor.set_decorations`, char
columns converted to UTF-8 byte offsets; styles re-applied in
`InkEditor.on_mount` because before mount the editor cannot see plugin
styles), `api.markdown_extension` (registry cleared at app init),
`api.provide`/`api.service`, events `document_changed` and `panel_closed`,
and manifest `[[requires]]` (`command` or `any_of`, `optional`, per-platform
`install`).

- Spelling bundles a SCOWL en_US list (aspell-en dump, 123,692 words, 322 KB
  gz; license file alongside). `.gitattributes` marks `plugins/**/*.gz`
  binary, since `plugins/**` is forced to LF. Thesaurus is online
  (Datamuse); no offline thesaurus data was available.
- Menus: Binder moved to its own "B&inder" menu (Alt+I) because Alt+B is Go
  Back; Comments has "&Review" (Alt+R); AI has "&AI" (Alt+A).
  `test_menu_accelerators_are_unique` guards letters in every menu.
- Keys added: Ctrl+F2 spell, Alt+F1 thesaurus, F8 outline, Ctrl+F5
  snapshot, Ctrl+F8 progress, Alt+J journal, Alt+C comment, Alt+L follow
  link, Alt+Left link back, Ctrl+T panel. `key_conflicts()` is asserted
  empty with every plugin loaded.
- Manuscript DOCX: pandoc's default reference.docx with styles.xml and the
  sectPr rewritten by regex; no running header (Surname / Title / page),
  which would need a header part.
- AI: stdlib urllib SSE for Anthropic Messages and OpenAI chat
  completions; default model claude-sonnet-5-5; keys in env or
  `<config>/ai/<provider>.key` (0600), never settings.toml; per-host consent
  stored in settings. Tested against a local fake server only.
- Word Goal moved back to `examples/plugins/word_goal/` (Progress replaces it).

## Claude Code provider (0.4.0)

Aaron asked (2026-11-06) for the AI plugin to use the `claude` CLI headless so
requests bill to his Claude plan (he runs claude on Termux), with memory
across long writing sessions.

- `plugins/ai/claudecode.py` runs `claude -p` per request: stream-json with
  partial messages, `--strict-mcp-config`, `--setting-sources ""` (no user
  settings, hooks or CLAUDE.md; verified for project CLAUDE.md), and
  `--tools ""` or `Read,Grep,Glob` plus `--allowedTools` and `--add-dir`.
  Never `--bare` (it refuses OAuth). Prompt on stdin (Windows argv cap; no
  stdin makes claude wait 3 s). Errors arrive on stdout as a `result` with
  `is_error`; "No conversation found" raises SessionMissing and the plugin
  starts a new session.
- One session per project folder (binder's folder, else the document's
  folder), ids in `<state>/ai/claude-code-sessions.json`; `--session-id` on
  the first turn, `--resume` after. Claude Code files sessions by cwd, so
  every run starts in the project folder.
- The system prompt is frozen at the first request of a conversation
  (`--system-prompt-snapshot` default on), so current text always goes in
  the message. With file access, prompts name files; unsaved buffers are
  written to `<state>/ai/current/` and that folder is passed with --add-dir.
- Story bible (`Story Bible.md` in the project folder) for every provider;
  B in the reply panel appends a reply.
- Termux has no official claude build; `command` accepts a full command
  line. A proot-distro claude only works if Inkmill runs in the same distro.
- Verified end to end against the real claude 2.1.318 (file reads,
  resume memory, unsaved copy, live tmux run); tests use
  `tests/fake_claude.py`.

## Self-update (0.4.1)

Aaron asked (2026-11-06) for update checking and self-update where
feasible, with a notice of what to do where not.

- `src/inkmill/updates.py`. Newest version = `__version__` in
  `src/inkmill/__init__.py` on main (raw.githubusercontent, like the plugin
  index); notes = CHANGELOG sections newer than the running version.
  `INKMILL_UPDATE_URL` overrides the folder URL (tests use a `file://`
  folder; conftest points it at a missing folder so no test reaches GitHub).
- `detect()` reads `direct_url.json` and `<prefix>/pipx_metadata.json`.
  pipx: `pipx upgrade inkmill` (keeps injections), but `pipx runpip inkmill
  install --upgrade git+<url>` when the venv or pipx's recorded spec names a
  branch or tag, because `pipx upgrade` reinstalls the recorded spec. A
  live test caught that: it silently went back to the pinned branch.
  pip: `python -m pip install --upgrade [--user] git+<url>`; the bare
  `git+URL` form, since pip 24 rejects `name @ git+file:///...`.
  Editable installs, PEP 668 system Pythons, unwritable site-packages and
  missing pip get the manual command and a reason.
- Windows: never in-process (locked files). Update and Quit sets
  `app.pending_update`; `__main__.after_exit` starts PowerShell in a new
  console that `Wait-Process`es on Inkmill's pid, then runs the command.
  Untested on real Windows.
- After installing, `installed_version()` asks a fresh interpreter, and
  the update counts as done only if that is newer. Restart is `os.execv` of
  `python -m inkmill <session paths>` after the normal quit flow (the
  in-process plugin restart cannot load new core code).
- Verified live in a scratch pipx home and venv: a pinned pipx install, the
  in-app Install then Restart into the new version, `--update` for pip.

## Rich view and reading view (0.5.0)

Aaron asked (2026-11-11) for a formatted editor view, toggleable against raw
Markdown. He chose step 1 (styled source, nothing hidden) plus a read-only
reading view; concealing markup on non-cursor lines (live preview) was
deferred because TextArea has no display-to-source mapping and it would mean
building on Textual internals.

- `src/inkmill/richtext.py`: `line_kinds()` is the only whole-document pass
  (front matter, fences, tables, setext, rules); `spans_for(line, kind)` is
  lru-cached per line. Style names `rich.*` live in `themes.syntax_theme`;
  a test asserts every name used exists in every built-in theme.
- `InkEditor` swaps `_highlights` for `_RichHighlights`, whose `__missing__`
  styles a row when TextArea first draws it (`__bool__` is True because
  render_line checks the dict's truthiness). Rich mode skips tree-sitter,
  which made it faster than raw on an 82k-word file (101 vs 148 ms per
  pilot keystroke). Plugin decorations are appended after, so they draw on top.
- Tables tidy while typing in rich mode only, via `tidy_table_while_typing`
  from `on_text_area_changed`, keeping the cursor's cell and offset. Undo
  and redo set `_undoing` so the next change is not re-tidied (otherwise
  undo would loop). Undo inside a table steps per keystroke.
- Reading view: `screens/reading.py`, Textual `Markdown` widget. `reading_text`
  keeps the line count (front matter blanked, footnote refs to superscripts,
  defs joined with hard breaks, task boxes to check boxes) so `source_range`
  finds the cursor's block. Keys Alt+F3 (rich, WordPerfect's Reveal Codes)
  and Shift+F7 (reading); menu letters R&ich and Re&ading because the Themes
  plugin holds G and R in the View menu.

### 0.5.1 emphasis colors

Aaron saw no bold or italic in 0.5.0 (markers dimmed, nothing else). The SGR
codes were emitted (ESC[1m, ESC[3m seen in `tmux capture-pane -e`), so the
terminal could not draw them: likely the laptop's Ghostty DOS profile (bitmap
VGA font, `bold-color = bright`, no italic face), and Windows Terminal draws
bold as bright by default, which white text already is. Fix: `im-bold` and
`im-italic` theme colors (UI_KEYS), derived with a 4.5:1 contrast floor,
applied in syntax_theme and to Markdown `.strong`/`.em` in the reading view;
`emphasis_colors` setting and View > Emphasis Colors. Validated with real
xterm screenshots on Xvfb (normal font, and `-fn 9x15` with bold disabled),
driven through tmux send-keys; xwd parsed with PIL. Textual's SVG export
always shows bold and italic, so it cannot validate this.

### 0.5.2 format commands

Aaron reported Italic inserting `**`, Bold `****` and Inline Code `~~`. The
first two were the empty-pair design (cursor between `*` and `*`); Inline
Code inserting `~~` did not reproduce (menu letter, arrows and Ctrl+P all
ran format.code with plugins loaded), most likely two backticks drawn by his
font. `toggle_wrap` now takes a placeholder: word under the cursor first,
else markers around a selected placeholder; `_closes_here` steps past the
closing marker on a second press; `_has_markers` uses the run of `*`/`_` so
italic and bold combine. In the rich view `_RichHighlights` appends a
`rich.selected` range for the selection (TextArea draws highlights after the
selection), updated from `_watch_selection`. Real-terminal check: keys sent
back to back with tmux send-keys gave a garbled run; pacing them 0.4 s apart
worked (cause not investigated).

### 0.5.3 save conversation

Aaron asked (2026-11-12) to keep a several-turn Claude Code conversation in
the binder's research. AI > Save Conversation as Research Note reads the
session id from the sessions store and the transcript from
`<CLAUDE_CONFIG_DIR or ~/.claude>/projects/*/<id>.jsonl` (globbed, since
Claude Code's folder-name encoding is its own). `plugins/ai/conversation.py`
holds the command wording (FEEDBACK, SUMMARY, REWRITE, CONTINUITY, source
markers) so the parser can name each request's command and drop the
"Project folder:" header. Requests are user records with string content;
tool results are user records with list content and no text; each reply
block is its own assistant record. Replies keep only text after the last
tool use, like the panel. Binder 1.2 `Service.add_research_note` (shared
with Clip Web Page) writes and links the note, never overwriting. Verified
end to end against real claude with haiku.

Same PR, at Aaron's request: the reply panel shows the request above the
reply and pages through turns (Left/Right and `[`/`]`, L list, AI >
Conversation History). `ReplyPanel` holds `entries` (conversation.Exchange)
plus an optional live entry that streams; R and 1-3 act only on the live
entry. Claude Code turns come from the transcript (re-read per panel,
cached by mtime and size); other providers keep a per-project in-memory
list in `state["memory"]` until quit, documented as Claude Code only for
now. `TurnList` filters across request and reply text. Checked in tmux
with the plugin symlinked into a scratch `<config>/plugins` (the app loads
plugins from there, not the repo).

### 0.5.4 lasting conversation record

Aaron asked (2026-11-12) for conversations that outlive Claude Code's
30-day `cleanupPeriodDays` clean-up, a way to page saved notes, and an
import helper. `conversation.Log` appends JSON lines to
`<project>/.inkmill/ai-conversation.jsonl` (types `turn`, `reset`; a turn
carries session, provider, source and a UTC `time` from `stamp()`).
`history()` syncs a Claude Code transcript into the log by count per
session (`Log.sync` appends `items[count(session):]`), so sync must run
before each live append; `run()` calls `history()` before sending, which
does that. Display sorts by time. `run_cli` puts a `SEED_START...SEED_END`
block before the first request of a new session when the log holds turns
since the last reset (files on: writes `.inkmill/earlier-conversation.md`
and names it; files off: inlines up to max_context_chars/4);
`strip_seed()` removes it when a transcript is read. New Conversation
syncs, forgets the session and writes a reset. `from_markdown()` reverses
`to_markdown()` for AI > Show Saved Conversation. `claudecode.Reply.tools`
carries the tool calls so live turns record Looked at. Core
`--import-conversation FOLDER --from SOURCE` finds the `ai` plugin with
`plugins.discover()` and calls its module-level `import_conversation`
(sources: linked session, `all` by transcript `cwd`, session id, `.jsonl`,
saved `.md` note deduped by label, request and reply). Setting
`keep_history` (default true) turns the log off.

Same PR, at Aaron's request: AI > Update Story Bible from Conversation
(`plugins/ai/bible.py`, pure: `request`, `parse` of a JSON array of
{section, entry, note}, `merge` appending bullets at the end of the
matching `##` section, case-insensitive, new sections at the end). It is a
one-off request (`persist=False`, not logged); with Claude Code files on,
the conversation goes to `.inkmill/conversation-for-bible.md`. `BibleReview`
is an OptionList with drawn `[x]` marks (Textual's SelectionList misplaces
checkboxes on wrapped items); Space and A are screen bindings, not on_key,
so they run after a queued arrow move (checked in tmux). A
reply that is not JSON falls back to the reply panel. Verified with real
claude haiku: settled facts proposed, the undecided brother left out.

### 0.5.5 document titles

Aaron asked (2026-11-12) to name a document by something other than its
file name in List Files. Front matter `title` (the key Binder, Links and the
exports already read) now shows in List Files (`Entry.shown`, I toggles),
the status line (`fit_title`: title kept, path clipped from the left; below
`MIN_PATH` cells only the title and the unsaved marker) and the Ctrl+L list.
One setting, `show_titles`, default on. `documents.read_title` reads the
first 8 KB, cached by mtime and size; `Document.display_title` parses only
that much of the buffer, so it is cheap per keystroke. Only Markdown
formats carry titles, and there is no heading fallback (unlike Binder's
`title_of`). Fixed on the way: `refresh_listing` read the highlighted path
after replacing the entries, so a re-sort kept the row, not the file.
The Name column is capped at what the list pane has left (`_name_room`,
recomputed on resize), since the four-digit-year date column made 32
cells overflow a 100-column screen. `docs/screenshots/files.png` was
regenerated from `app.save_screenshot` SVG, rendered by headless Edge and
cropped with Pillow (shared venv); the directory label was set to the
original demo path.

### 0.5.6 AI edits

Aaron asked (2026-11-12) whether the AI chat can edit the document, then
asked for two additions. AI > Continue Writing (`ai.continue`, no dialog)
sends `CONTINUE` plus `ENDS_HERE` and the text before the cursor
(`continue_context_chars`, 6000) and `FOLLOWS` with up to 1500 characters
after it, asking for `continue_words` (300). `state["anchor"]` holds (doc
id, index, the 200 characters before it); `ReplyPanel(continuation=True)`
makes I call `insert_continuation`, which inserts at the anchor when that
text is unchanged, otherwise at the cursor, using `edits.join` for the
space or paragraph break, then moves the anchor after the insert so a
follow-up continues from there. `state["continuation"]` carries this to Q
follow-ups.

AI > Suggest Edits (`ai.suggest_edits`) asks for a JSON array of {find,
replace, why} (`conversation.SUGGEST`; the fake claude answers any "Reply
with only a JSON array" prompt from FAKE_CLAUDE_REPLY). It goes through
`send_once`: part of the project's conversation (persisted, header and
bible as in `ask`) but with no reply panel, and logged with the edits as a
Markdown list. `edits.locate` finds each `find` after the previous one,
then from the start; skips edits that overlap, touch CriticMarkup or are
not found; and `narrow` splits each into word-level changes with difflib
(the reason stays on the first piece), since real haiku quoted context and
folded two fixes into one edit. Whole-document scope is the body after
front matter. With the comments plugin enabled, the scope is replaced in
one editor edit by `{~~old~>new~~}{>>why<<}` marks and `comments.review`
opens; otherwise `EditReview` (the bible checklist, now a `CheckList`
base) applies the chosen ones. Comments & Track Changes 1.1 treats an
add, delete or replace followed by a comment as one mark. Checked live in
tmux with real claude haiku: 3 edits marked, A and R resolved them with
their reasons; a continuation inserted at the end with a space join.
